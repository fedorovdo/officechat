Для RED OS контрольная копия смены хранилища проверена локально и на новой
площадке: `SUCCESS`, `PROTECTED`, тип `pre_storage_change`, `verify-backup`.
Изолированный restore-drill внешнего экземпляра прошёл: 35 таблиц,
35 relations, одно расширение, Alembic `20260728_0026` (head).
Источник и проверяющий контейнер использовали PostgreSQL 16.15.
После проверки `/health` и `/ready` отвечали, таймер оставался enabled/active.
Для Debian ID контрольной копии RC13.36 зафиксирован по экрану операции;
отдельный restore-drill этого экземпляра не представлен.

## Оставшаяся приёмка

Следующие сценарии ещё не имеют полного набора результатов:

- NFS на Debian и RED OS, включая переход SMB/NFS.
- Полный перенос на чистую одноразовую ВМ с секретами приложения и Caddy CA;
  проверка сообщений и вложений после переноса.
- Прерывание исполнителя и перезагрузка именно во время смены площадки.
- Недоступность старого NAS во время отката, повторное восстановление журнала,
  смена SMB-сервера и учётной записи.
- Проверка итогового коммита после объединения в `main` и его релизной упаковки.

Список процедур остаётся в [руководстве по хранилищу и расписанию](../deployment/backup-destinations-schedule-ru.md).
Подтверждённые проверки выполнялись на малом тестовом наборе данных;
нагрузка, объём копий и ёмкость для 300 активных пользователей не измерялись.
