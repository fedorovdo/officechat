# OfficeChat 0.1.0-rc14 — подготовка кандидата

Кандидат ещё не опубликован. Документ не является инструкцией устанавливать
несуществующие образы. База — опубликованный RC13.39, commit
`e4b2079274f69bec8d3953dde6ac1ec87ba184bf`.

## Изменения относительно RC13.39

- В Backup Center показываются сохранённые режим и число дней хранения:
  агент читает RETENTION_MODE/RETENTION_DAYS из backup.conf.
- Перезапуск backup-agent сохраняет каталог сокета, примонтированный в
  backend; контейнеру не требуется перезапуск для восстановления связи.
- Добавлены регрессионные проверки чтения политики и systemd unit.

Прикладные возможности, схема БД, форматы архивов и сам алгоритм очистки
не меняются. Alembic остаётся `20261014_0027`. Существующие настройки сохраняются.

На тестовом Debian оба исправления проверены точечно; возрастная очистка days/5
подтверждена в обоих хранилищах, два рестарта агента прошли без смены каталога
или контейнера. Это не заменяет установку и обновление полного bundle RC14.

## До публикации

1. Проверить исходники и CI на точном SHA ветки `release/0.1.0-rc14`.
2. Выполнить Release Images с `version=0.1.0-rc14`,
   `ghcr_access_preflight_only=true`, `push_rc_tag=false`: этот режим выполняет
   проверки и GHCR access preflight, пропускает публикацию образов и артефактов.
3. После успешной проверки подготовить versioned сборку и prerelease RC14,
   проверить внешние/внутренние checksums, revision и image digests.
4. Выполнить чистую установку на Debian 13 и обновление действующего тестового
   Debian RC13.39. Проверить сохранность данных, CA, SMB, таймера и days/5.
5. Проверить restore и reboot, а для заявления поддержки RED OS — выполнить
   отдельную приёмку на RED OS 8 с SELinux Enforcing.

## Простая установка после публикации кандидата

Точка входа остаётся `officechat-install.sh --version 0.1.0-rc14 --hostname ИМЯ`.
Сначала скачать installer и checksum из соответствующего GitHub Release,
проверить checksum, затем запускать под root с доступом к приватным GHCR packages.
Полный порядок: [INSTALL_RU.md](../INSTALL_RU.md).

Для проверки нужен новый Debian 13 amd64 сервер с отдельным DNS-именем.
Действующую тестовую VM и production для чистой установки не очищать.
