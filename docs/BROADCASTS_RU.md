# Broadcast Announcements v0.1

## Назначение

Broadcast Announcements — отдельный механизм корпоративных объявлений. Он не создаёт по одному direct message на каждого получателя: текст объявления хранится один раз, а таблица получателей хранит статус доставки, прочтения и скрытия.

## Доступ

Создавать, просматривать preview, отправлять, смотреть свою историю и отзывать рассылки может только пользователь с эффективным правом `can_broadcast`. Роли `admin`, `moderator` или владелец группы сами по себе не дают это право. Bot, disabled и service users не могут быть отправителями.

Обычный пользователь может видеть только объявления, адресованные ему:

- `GET /api/announcements`
- `GET /api/announcements/unread`
- `GET /api/announcements/{announcement_id}`
- `POST /api/announcements/{announcement_id}/read`
- `POST /api/announcements/{announcement_id}/dismiss`

Открытие объявления помечает его прочитанным.

## Отправка

Sender flow:

1. Подготовить заголовок, текст, приоритет и аудиторию.
2. Выполнить `POST /api/broadcasts/preview`.
3. Проверить точное число получателей и confirmation token.
4. Выполнить `POST /api/broadcasts`.
5. Выполнить `POST /api/broadcasts/{broadcast_id}/send` с `expected_recipient_count`, `confirmation_token` и `idempotency_key`.

Для срочной рассылки всем активным пользователям UI требует дополнительное подтверждение словом `РАЗОСЛАТЬ`.

## Аудитория

Поддерживаются аудитории:

- `all_active_users`
- `selected_groups`
- `selected_users`

Из получателей исключаются отключённые пользователи, bot users и service/system users. Для `selected_users` невалидные пользователи отклоняются как ошибка, чтобы отправитель не думал, что они получили объявление.

## WebSocket

Используется существующий персональный канал:

```text
WS /api/ws/me?token=...
```

События:

- `announcement.created`
- `announcement.read`
- `announcement.retracted`

Это отдельный unread counter для объявлений; он не смешивается с unread counters чатов.

## Безопасность и аудит

Audit Log записывает только безопасные metadata: тип аудитории, приоритет, количество получателей и технические счётчики. Заголовок, тело объявления, usernames получателей, confirmation token и idempotency key не пишутся в audit details.

Rate limiting выполняется через Valkey. Текущие переменные:

- `BROADCAST_TITLE_MAX_LENGTH=160`
- `BROADCAST_BODY_MAX_LENGTH=10000`
- `BROADCAST_MAX_RECIPIENTS=10000`
- `BROADCAST_MAX_PER_HOUR=10`
- `BROADCAST_PREVIEW_TTL_SECONDS=300`
- `BROADCAST_RETENTION_DAYS=365`

## Ограничения v0.1

- Нет scheduled announcements.
- Нет произвольного HTML, встроенных картинок и ссылок в форматированном тексте.
- Нет обязательного подтверждения прочтения.
- Нет вложений в объявлениях.
- WebSocket delivery single-instance; для production multi-instance нужен Valkey pub/sub.

## Центр уведомлений

При отправке broadcast для каждого получателя создаётся notification типа `announcement`. Она ссылается на announcement ID и не копирует полное тело объявления. Счётчик объявлений и счётчик центра уведомлений независимы; открытие объявления отдельно помечает связанную notification как прочитанную.


## Редактор и шаблоны объявлений

Новая форма поддерживает жирный, курсив, подчёркивание, три размера текста
(14, 18 и 24 px), выравнивание слева/по центру/справа, маркированные и
нумерованные списки, снятие форматирования, отмену и повтор. Форматирование
видно в редакторе и у получателя. Старые текстовые объявления отображаются
как прежде, включая переносы строк. Вставка из буфера переносит обычный текст;
HTML, внешние картинки, ссылки и произвольные стили из буфера не сохраняются.

Для повторяющихся сообщений, например «Сегодня привоз воды»:

1. Пользователь с `can_broadcast` заполняет заголовок, сообщение и приоритет.
2. В блоке «Шаблоны объявлений» вводит название и нажимает
   «Сохранить объявление как шаблон». Сохранение не отправляет рассылку.
3. Любой пользователь с `can_broadcast` может выбрать общий шаблон кнопкой
   «Использовать», изменить копию текста для конкретного случая и выбрать аудиторию.
4. Перед отправкой обязательно заново проверить получателей. Применение шаблона
   сбрасывает preview, confirmation token UI, слово срочного подтверждения и draft ID.
5. Только создатель может редактировать исходный шаблон в отдельной форме или
   удалить его после подтверждения. Другим отправителям эти кнопки недоступны;
   прямой запрос API также запрещён. Исключения для admin/superadmin нет.

Шаблон содержит название, заголовок, обычный текст, форматирование и приоритет.
Аудитория, confirmation token, пароль и состояние доставки в шаблон не входят.
База общая для пользователей с правом объявления; список разбит на страницы.
Применение создаёт самостоятельный черновик: изменение или удаление шаблона
не меняет уже отправленные объявления. Отзыв объявления скрывает и обычное
тело, и форматированный документ.

### API и хранение

| Метод | Путь | Назначение |
| --- | --- | --- |
| GET | `/api/broadcast-templates?page=1&limit=20` | Общая база для отправителей |
| POST | `/api/broadcast-templates` | Создание с владельцем из текущей сессии |
| PUT | `/api/broadcast-templates/{id}` | Полная замена содержимого своим автором |
| DELETE | `/api/broadcast-templates/{id}` | Удаление своим автором |

Все операции требуют действующего `can_broadcast` и активного человека.
Изменение чужого шаблона возвращает 403, отсутствующего — 404. Передать или
заменить `created_by_user_id` через payload нельзя. Если учётная запись автора
удалена, шаблон остаётся доступным для использования, а изменение и удаление
без автора запрещены. Приватное содержимое в audit не записывается; фиксируются
`broadcast.template_created/updated/deleted`, actor и ID шаблона.

Миграция `20261014_0027` добавляет nullable JSONB `body_doc` существующим
объявлениям и таблицу `broadcast_templates`; существующие объявления и пароли
не меняются. Сервер принимает только ограниченное дерево форматирования:
разрешённые узлы/marks, фиксированные размеры и выравнивания; проверяет
совпадение обычного текста с документом, глубину, число узлов и размер.
Рендер получателя использует React-элементы, без `dangerouslySetInnerHTML`.

После обновления требуется `alembic upgrade head`. Шаблоны входят в обычный
полный дамп PostgreSQL и восстановление. `downgrade` удаляет таблицу шаблонов
и поле форматирования, поэтому перед ним необходимо сохранить копию БД.

### Приёмка перед выпуском

- Создать двух отправителей с `can_broadcast` и пользователя без этого права.
- Отправить объявление с жирным/курсивом/подчёркиванием, размером, выравниванием,
  обоими списками; сверить вид у получателя и обычный текст legacy-клиента.
- Сохранить шаблон «Вода», использовать его от второго отправителя, подтвердить
  новую аудиторию и отправить самостоятельную копию.
- От второго отправителя и superadmin проверить API PUT/DELETE чужого шаблона:
  403 без изменения данных. Без `can_broadcast` проверить все четыре операции.
- Автором отредактировать и удалить шаблон: старое отправленное объявление
  остаётся прежним. Проверить обычное текстовое объявление и отзыв rich text.
- Проверить вставку из Word/браузера, отмену/повтор и клавиатуру на Chrome/Edge
  и Firefox. Провести CI с миграцией PostgreSQL, затем backup/restore-drill
  сборки с новой Alembic head, включая сохранение шаблонов.
