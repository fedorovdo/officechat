# Prepare RC14 from RC13.39 with backup agent fixes

Backup Center RC13.39 показывал значения хранения по умолчанию вместо
сохранённых RETENTION_MODE/RETENTION_DAYS. Рестарт агента мог пересоздать
runtime-каталог и оставить backend с устаревшим bind mount. Кандидат читает
сохранённую политику и задаёт RuntimeDirectoryPreserve=yes в поставляемом unit.
Добавлены регрессионные проверки и документы приёмки.

База этой ветки — опубликованный RC13.39, commit
`e4b2079274f69bec8d3953dde6ac1ec87ba184bf`. GitHub main на момент подготовки
указывает на `1176b7e` и отстаёт от тега на 31 commit; поэтому PR в main включает
ранее выпущенные изменения. Новые изменения проверять также отдельным сравнением
с тегом `v0.1.0-rc13.39-redos8-debian13-installer`. Force push/reset main не нужен.

## Подтверждение на Debian

- Ночные копии и age retention days/5 за 20–24 октября проверены в local/SMB.
- Drop-in установлен 24 октября; два рестарта агента сохранили inode каталога,
  container ID/StartedAt backend, config hashes и доступ к status.
- `BACKUP_AGENT_RUNTIME_FIX=PASS`, `/root/officechat-socket-fix.vVFHnJ`.
- Агент healthy, SMB mounted/copied, timer enabled/active; предупреждений нет.
